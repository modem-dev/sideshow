sideshow.sh — a hosted, multi-tenant offering

GitHub sign-in for humans · per-user agent tokens for agents · everything on Cloudflare

Request flow

human / browser agent edge routing + auth global directory per-user board (Durable Object)

The whole stack stays on Cloudflare

Durable Objects — per-board data

Sessions, surfaces, comments, assets stay in each user's DO SQLite. SqlStore is unchanged. The board is the database and the event bus.

D1 — the only new store

Small global directory: GitHub user → board, hashed agent tokens, OAuth login sessions. Read-heavy, isolate-cached on the token hot path.

Workers — edge

Identity resolution + routing, the OAuth dance, token mint/revoke, and serving the viewer shell.

R2 / KV — optional, later

R2 for cheaper big assets (already content-addressed by SHA-256). KV as a hot read-cache for token→user. Not needed for v1.

What changes vs today

  • One line of routing. idFromName("default") → idFromName(userId). Each user gets their own isolated DO.
  • Auth generalized. Today's single shared SIDESHOW_TOKEN becomes per-user, revocable agent tokens; self-host keeps the single-token tier.
  • Two new auth flows. GitHub OAuth for browsers; mintable Bearer tokens for headless agents (shown on a "connect agent" page).
  • Core stays runtime-agnostic. All new OAuth / routing / directory code lives in workers/ — server/ stays clean.

Rollout

  1. Directory + token model. D1 users + tokens tables, mint / resolve / revoke, isolate cache.
  2. Per-user routing. workers/ resolve identity → route to the user's board DO; generalize the app auth seam.
  3. GitHub OAuth. edge /auth/github + callback, signed session cookies.
  4. Viewer UX. viewer/ sign-in/out, "connect agent" page with copy-paste MCP/CLI config, token management.
  5. Ops. deploy sideshow.sh DNS → Worker route, GitHub OAuth app, bindings, account delete, rate limits.

Bottom line: it's "GitHub OAuth + a token directory + per-user routing," not a re-architecture — the Durable-Object-per-board model was already latent in the design, so the hard part is done.
